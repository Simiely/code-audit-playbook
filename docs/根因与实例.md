# 根因与实例 · L5 判定手册与「一坑一篇」

> 本文件是 [`DEVELOPMENT.md`](../DEVELOPMENT.md) 中 **L5 根因分析** 的配套材料：
> 第二部分是**根因分类表**（L5 的判定手册）；第三部分是**五个脱敏实例**（一坑一篇）。
> 实例均来自真实审计，已按隐私红线脱敏 —— 保留**推理链**，去掉可追溯细节。

---

## 一、判据

L5 对每条发现追问三层：

```
症状 → 为什么没拦住？ → 为什么没发现？ → 结构性缺陷是什么？
```

第三层的答案基本落在下面的五类里。**判定是否真的找到了根因，看这一条**：

> **修完它，同类问题不会再出现在别处。** 否则就是补丁，不是根因。

---

## 二、根因分类表（五类结构性缺陷）

**每类都有对应的「一次修好」的办法**：

| 结构性缺陷 | 症状特征 | 一次修好的办法 |
|---|---|---|
| **同一规则多处实现** | 补丁打在一处、另一处仍漏 | 合并为唯一实现，全站只留一份 |
| **不变量无归属者** | 每个模块都以为别人会管 | 指定唯一归属（DB 约束 / 单一校验函数 / 门禁） |
| **契约只写在注释里** | 文档说「保证不抛」，实际会抛 | 用测试固定契约，而非靠注释 |
| **鉴权/校验按形式而非按性质** | 按 HTTP 方法、按字段名等「形式」判断 | 改为按路由敏感度、按数据性质分级 |
| **验证只覆盖检测、不覆盖修复** | 巡检能发现问题、修复动作永远跳过 | 检测与修复共用同一判据 |

> 第 5 类「检测与修复判据不一致」正是 **L7 发布后响应** 要制度化的内容 —— 不应只停留为一个实例。
> 第 3 类「契约只写在注释里」对应外壳 **E2 证据第④层** —— 注释与口述不是证据，是待证伪主张，必须用重跑 / 工具产出（①②级）佐证（见 [`外壳.md`](./外壳.md)）。

## 三、实例（一坑一篇 · 脱敏）

### 实例 1：URL 安全校验存在两份独立实现

**TL;DR**：同一类「只允许站内相对路径」的校验被写了两遍，补丁只打在其中一份上，另一份成了漏洞入口。

- **问题**：登录后的回跳参数可以跳到站外 —— 用反斜杠开头的路径绕过了「禁止 `//` 开头」的判断，而浏览器会把反斜杠归一成斜杠
- **根因**：**同一规则两处独立实现，无单一真源** —— 一处后来补了反斜杠判断，另一处没跟上
- **解决**：合并为唯一的路径校验函数，所有回跳 / 返回目标统一调用它
- **预防**：同类校验只允许存在一份实现；新增校验点前先搜是否已有

---

### 实例 2：敏感端点只靠方法级鉴权

**TL;DR**：鉴权中间件按 HTTP 方法划分，导致承载全量数据的 GET 端点未登录即可读取。

- **问题**：全量数据导出、备份列表、回收站列表等 GET 端点，在「外网可见」开关打开时，任意未登录的互联网用户即可下载整库快照
- **根因**：**鉴权按形式（HTTP 方法）而非按性质（路由敏感度）** —— 中间件只拦写方法，GET 一律放行，而代码注释却写着「外网需登录」
- **解决**：引入路由敏感度分级（公开 / 需登录 / 仅局域网），敏感 GET 显式挂「非局域网必须带会话」的校验
- **预防**：端点矩阵测试 —— 遍历所有路由 × {未登录, 局域网, 外网} × {读, 写}，断言预期结果

---

### 实例 3：巡检判定与修复动作判据不一致

**TL;DR**：巡检能正确列出待修条目，但修复动作对同一批条目永远跳过，问题永不收敛。

- **问题**：巡检任务每天列出「缺缩略图」的条目，修复任务每天对它们空转 —— 缩略图永远补不回来
- **根因**：**两处判据各写各的** —— 巡检按「有无缩略图」判待修，修复按「有无主图」判跳过
- **解决**：修复判据同时检查缩略图缺失；巡检不再把「本就不可能生成缩略图的格式」算作待修
- **预防**：检测与修复**共用同一个「待修」判据函数**，不允许各写一份（→ 已制度化为 L7）

---

### 实例 4：引用完整性不变量无归属者

**TL;DR**：删除容器后从回收站还原条目，条目指向的容器已不存在，数据进入无法自愈的状态。

- **问题**：删除一个容器节点后，从回收站还原其中的条目 → 条目指向的容器已不存在，页面显示为空，且无法通过界面修复
- **根因**：**跨模块不变量没有归属者** —— 删除侧只查了一半（仅统计在用条目，漏了已软删的），还原侧完全不查，数据库层也没有约束
- **解决**：把归属指定给**数据库层**（外键 + 删除策略），三处不再各自为战
- **预防**：每条跨模块不变量都必须指定**唯一归属**（DB 约束 / 单一校验函数 / 架构门禁），并写明在文档里

---

### 实例 5：模块契约只写在注释里

**TL;DR**：模块注释写着「对外保证不抛异常」，实际在磁盘异常时冒泡，导致「用户看到失败、数据其实已写入」。

- **问题**：某个「保证不抛」的模块，在磁盘异常时把异常冒泡给调用方 → 用户看到失败提示，但数据其实已提交；重试只会拿到 404
- **根因**：**契约只存在于注释，没有强制点** —— 对外入口包了 try/catch，但它调用的内部函数没有
- **解决**：把 try/catch 提到对外入口，覆盖整段调用链
- **预防**：契约要用**测试**固定（注入故障、断言对外不抛），而不是靠注释（→ 已制度化为外壳 **E2 证据层级**：注释/口述是第④层，必须用①②级佐证）
