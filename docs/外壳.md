# 外壳 E · 审计的元结构

> 内核（十层，见 [`DEVELOPMENT.md`](../DEVELOPMENT.md)）决定「怎么干活」；**外壳决定「这是不是一次审计」**。
> 外壳吸收 ISO 19011 的审计元结构（**准则 / 证据 / 发现**）与 IIA 的证据标准，本地化为代码审计用语。
> 证据强度沿用仓库约定：★★★ 同行评议/标准 · ★★ 单点或大厂数据 · ★ 厂商自述/二手（待复核）。

---

## 为什么需要外壳

- **审计永远基于抽样**：它能证明「覆盖了什么」，**不能证明「没漏」**（ISO 19011）★★★。
- **顶层断言会预设结论**：assurance case（GSN/CAE）被批评为容易产生确认偏误与**假信心** —— 顶层 claim 一旦先定下来，论证就变成自我实现的预言（Nimrod 事故调查的批评；Leveson 更直言见过的 GSN 案例几乎都含确认偏误）★★★。
- 没有外壳，十层只是「**一套检查动作**」，不是「**一次审计**」—— 它能产出清单，但回答不了「这是谁审的、凭什么这么判、证明了什么」。

---

## E1 · 审计准则（criteria）—— 「什么算问题」

= L0 产出的**不变量清单** + 各层的判定标准。

**硬规则：每条发现必须能指到一条准则，否则不算发现。**

这一步把「凭感觉说这里不对」挡在外面，也让「发现」可复核：别人拿着同一条准则、同一份证据，应能得出同样的判断。准则即「按不变量审」里的不变量 —— 没有准则，「发现」与「个人口味」无法区分。

## E2 · 审计证据（evidence）—— 「什么算证据」★ 本方案最关键的构件

吸收 **IIA 证据四性**：**充分（sufficient）/ 可靠（reliable）/ 相关（relevant）/ 有用（useful）** ★★★，并按可靠性分四级：

| 层级 | 代码审计里的对应 | 可靠性 |
|---|---|---|
| ① **重跑 / 重验** | 你亲自执行、测试、复现得到的结果 | 最强 |
| ② **独立工具产出** | SAST / fuzzer / CI 的**原始输出**（非转述） | 强 |
| ③ **文档与配置** | 设计文档、配置、提交历史 | 中 |
| ④ **口述与注释** | 注释写的「保证不抛」、开发者的口头说法 | **最弱，必须用 ①② 佐证** |

> **注释不是证据，是待证伪的主张。** 这正是实例 5 的教训（注释写「保证不抛」、实际在磁盘异常时冒泡）；IIA 同样规定「询问（inquiry）单独不构成证据，必须佐证」★★★。

**留痕格式**：每条证据带 `file + function + commit SHA`，并指向 **CI 产物**（测试日志 / 覆盖率报告 / 扫描原始输出），**不接受口述**。

**抽样方法与局限声明**：用什么方式抽样（判断 / 统计）、样本量、结论能外推到什么程度 —— **写出来**。审计的可信度不来自「查了 100%」（那不现实），来自「说清了查了多少、凭什么外推」。

## E3 · 审计发现（finding）—— 证据 vs 准则的比对产物

每条发现统一为四元组，并判三类：

```
发现 = 准则引用 + 证据引用 + 证据层级(①–④) + 置信度
判定 = 符合 ｜ 不符合 ｜ 改进机会
```

证据层级为 ④ 且无 ①② 佐证时，发现不得直接定级为「不符合」，只能先记为「待证伪主张」。

## E4 · 独立性 —— 「谁审的」

- **发现与修复分离**（L6 已有）：发现的人不修，修完必须复检
- **高风险发现必须由非作者复核**（审查者 ≠ 作者）
- **AI 不得审 AI 自己写的代码**（L2.5 已有，自审盲区）
- **审查者指派：优先有该文件经验的人** —— 反馈有用率约 2 倍（65–71% vs 32–37%），且变更越大、有用率越低（Bosu, Greiler & Bird 2015，150 万条评论）★★★

## E5 · 声明边界 —— 「证明了什么、不证明什么」★ 改了核心口径

**把「覆盖率可证明」改为：「覆盖了什么」可证明，「没漏」不可证明。**

每次审计的结论必须写明三句：

1. **覆盖了什么**（可证明：如「47 条路由全部扫过、N 个不变量全部核验」）
2. **没覆盖什么**（不证明：如「第三方库内部逻辑、运行期并发时序」）
3. **抽样局限**（外推边界 + 置信声明：如「按风险抽样 30%，结论仅适用于已审范围」）

依据：ISO 19011「审计永远基于抽样，从不证明全部没问题」★★★；assurance case 的假信心教训 ★★★。**写明边界不是示弱，是让结论可信的前提。**

## 与内核的关系

```
E1 准则  ← L0 不变量清单（外壳的「准则」就是内核 L0 的产出）
E2 证据  ← L1/L4 的工具与执行产出（原始输出，层级 ①②）
E3 发现  ← 各层清单经 L5 定性后的比对产物
E4 独立性 ← L6 发现/修复分离 + L2.5 自审盲区
E5 声明边界 ← 约束所有层的结论表述（含 README 核心口径）
```
